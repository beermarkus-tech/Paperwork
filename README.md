# Paperwork

A Progressive Web App for local PDF triage. See the full spec in the project notes; this repo currently implements **Stage 1** of the development roadmap.

## Stage 1 — Foundational File System Access

This is a deliberate spike, not the finished app. It exists to prove one thing end to end: that a Chromium browser installed as a PWA on Android can pick a local folder and read its contents via the File System Access API. Everything else in the spec depends on this working.

What it does:

- Serves a single page with a "Choose inbox folder…" button.
- On tap, calls `showDirectoryPicker()` and lists every `.pdf` file found directly inside the chosen folder (name + size only — no rendering yet).
- Registers a minimal service worker that caches the app shell for offline reload.
- Ships a web app manifest so it can be installed to the home screen.

No IndexedDB persistence, thumbnails, renaming, or filing yet — that's Stage 2 onward.

## Running locally

No build step. Serve the directory over HTTP(S) (the File System Access API and service workers require a secure context — `http://localhost` counts):

```sh
python3 -m http.server 8000
```

Then open `http://localhost:8000/`.

## Deploying

A GitHub Actions workflow (`.github/workflows/deploy.yml`) deploys this repo's contents to GitHub Pages on every push to `main`.

**One-time manual step**: in the repo's Settings → Pages, set **Source** to **GitHub Actions**. After that, pushes to `main` deploy automatically.

## Testing on Android

1. Push to `main` and wait for the Pages deployment to finish.
2. Open the deployed URL in Chrome on Android.
3. Tap "Choose inbox folder…" and confirm the folder picker and file listing work.

If `showDirectoryPicker` is unsupported, the page disables the button and shows an explicit message instead of failing silently — that result itself is the point of this stage.
